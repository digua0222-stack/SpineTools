### 不可降低的约束

1. 不调用 MiniMax、Gemini 或其他云端图像生成、视觉分析服务。
2. 不请求运行时人工提供轮廓、候选编号、部件 Prompt 或修正文件；缺少必要信息时由程序
   推断、重试或失败，不进入 `WAITING_FOR_REVIEW`。
3. 模型和依赖安装完成后，推理支持断网运行；联网安装与离线推理分为明确入口。
4. 保护已确认的原图可见 RGBA；未知隐藏内容必须标为推测，不能称为真实还原。
5. 不通过合并四肢、添加整图兜底层、减少必需部件、缩小动作范围或放宽阈值冒充成功。
6. 不覆盖现有 SAM 产物和回归基线；基线修正、补全结果分别版本化。
7. 成功部件可以缓存，失败部件有界重试；任务失败不等于等待人工处理。

## 3. 自动补全路线

1. 校验并冻结原图、最终 SAM 掩码和坐标；恢复程序误删的可见像素。
2. 从部件名称、可见轮廓、父子骨骼、关节点及可选视频推断遮挡关系和动作所需覆盖区。
3. 自动选择补全路线：规则几何 → 已有可见素材移植 → 全形预测/局部模型补绘。
4. 自动生成完整轮廓与补图区，生成有限候选并只合成允许修改的区域。
5. 自动校正绘制顺序、计算新裁剪坐标并运行静态、关节旋转和已给定动作测试。
6. 先过硬性质量门，再排序；失败按固定策略重试，预算耗尽后返回失败并归档。

### 两类缺口不能混淆

- 可见像素丢失：从原图恢复并检查部件归属，禁止模型臆造。
- 遮挡纹理缺失：原图没有答案，由几何、参考素材或生成模型提出完整外观假设。

同一原图坐标可以同时拥有“手掌下面的枪杆”和“枪杆下面的胸甲”。完整部件允许合理
重叠，靠层级遮挡；补全后不得再全局执行互斥裁切，否则会再次切掉隐藏纹理。

### 候选模型的定位

- LaMa：局部纹理修复候选，不负责保证肩甲等部件的完整语义结构。
- SDXL Inpainting：局部有条件纹理补绘候选；Prompt 由部件元数据自动生成。
- pix2gestalt：完整轮廓/外观预测的对照候选，利用现有可见 mask，无需人工完整轮廓。
- Open-World Amodal Appearance Completion：遮挡分析和自动提示策略的研究参考，
  不默认导入整套依赖，也不假定其物体级能力能直接覆盖铠甲子部件。

以上都不是已验收的生产后端。AC-03 审核依赖及许可证，AC-04/05/08 验证角色域效果；
未通过的模型不得成为默认必需组件。不重训大模型作为 MVP 的前置条件。

- [ ] Alpha 根据完整轮廓构建，不按白/黑色抠图；颜色匹配仅作用于新增像素。
- [ ] 不使用“全局减色/锐化”更改已确认原画；模型、Seed、Prompt、Mask 均可追溯。

建议新增：`spinetools/completion/backends/`、`render.py`。
验收：透明 RGB 污染、背景矩形、修改保护区、生成区超界等负例被拦截；
至少一个后端在 H20 四类基准中形成可评测结果。不承诺不同 GPU/库版本生成图片逐字节一致。

### AC-09 — 自动绘制顺序、坐标与动作检查

- [ ] 基于遮挡假设建立有向关系，求解合法顺序；披风在躯干后，握持手在枪杆前。
  如出现局部互相穿插，自动拆分必要的绘制片段或拒收，不凭原列表顺序覆盖。
- [ ] 保持 `pivotSource`、骨长和源图锚点；新 `pivotLocal` 由完整裁剪框换算。
- [ ] 先实现独立的轻量 PNG/骨骼变换渲染器，不把尚未实现的 Spine 导出器或编辑器作为依赖。
- [ ] 静态检查重组、保护区、错层；动态逐关节扫描测试角度，并检查父子连接邻域，
  不能把手臂与身体正常分离后的背景误判为透明裂缝。
- [ ] 默认覆盖 `-15°～+15°`（含中间采样），另测组合姿态；有目标动作时额外覆盖动作帧。
- [ ] 报告合法隐藏层重叠和非法跨部件覆盖；不沿用补全前“非关节重叠一律扣分”的规则。

建议新增：`spinetools/completion/posecheck.py`、`draw_order.py`。
验收：正确前后关系通过、故意颠倒披风/手/枪失败；裁框变化无漂移；人为制造裂缝或缺图
的测试夹具必拒；范围及完整受检帧列表写入报告，不能只测零度姿势。

### AC-10 — 自动决策、有限重试与缓存

- [ ] 按硬性门限过滤候选，再按接缝、外观、改动面积和不确定性排序，规则及并列处理固定。
- [ ] 几何、参考路线各先尝试一次；生成路线最多 3 轮，每轮最多 4 个候选，即每部件
  最多 12 个生成候选。形状模型调用另有同等明确的上限，不藏在循环中无限生成。
- [ ] 扩大轮廓候选、替换自动参考、切换后端或 Seed 属于预定重试动作；禁止修改验收阈值。
- [ ] 成功部件缓存；原图、mask、模型、计划、策略或影响其遮挡的上游结果改变时失效。
- [ ] 部件/整轮有超时、任务总预算、显存不足处理；错误退出后仍输出 JSON 报告和已有诊断。
- [ ] 遮挡次序或组合动作失败时，失效并重试相关依赖部件，不能因为单部件分数高直接放行。
- [ ] 必需部件有失败则整包失败；可归档部分结果用于诊断，但不能标成可交付的最终包。

建议新增：`spinetools/completion/runner.py`、`selection.py`、`cache.py`。
验收：模拟超时、全候选失败、进程重启、缓存过期、缺模型时均有界结束；
没有交互式输入、浏览器点击或 `REVIEW` 等待状态；结果复现只保证固定已记录环境内的约定。

### AC-11 — CLI、安装入口与归档

- [ ] 提供 `plan/run/verify` 非交互命令，自动生成计划，用户不需要事先编写补图配置。
- [ ] 暴露输入 run、输出位置、可选视频/素材、设备、模型目录、Seed/预算/超时等参数。
- [ ] 内置默认策略，支持可选参数覆盖；这些覆盖不是成功运行的必需人工操作。
- [ ] `--dry-run` 不安装、不下载、不运行模型、不创建产物；`--offline` 下缺模型立即失败。
- [ ] 一键脚本完成依赖安装、探针、运行、验证和 tar；成功/失败都保存日志、状态与退出码。
- [ ] 归档不包含凭据、系统无关路径内容或大模型权重；不覆写已有 run 或未经确认的原图。
- [ ] 补全输出应能成为后续骨架/Atlas 模块的输入，但不把序列帧打包假称为骨骼验证。

建议新增：`scripts/completion/run-zhaoyun.sh`、运行手册和 CLI 测试。
验收：新 Docker 中从 clone 后一个非交互入口可跑；日志标识当前部件、后端、轮次、
候选及耗时；故障归档可重放诊断。无 GPU 的 CI 覆盖参数和失败路径。

### AC-12 — 赵云零人工验收与发布

- [ ] 第一关：枪杆断口、胸甲窄缺口、一个肘部连接区、披风缺口四类小样。
- [ ] 第二关：自动合成遮挡留出集，不使用人工候选或手绘完整 mask 调整结果。
- [ ] 第三关：完整角色必需部件；不能只检查“输出 23 张图”。`occludedParts` 中在目标
  动作下需要露出的部件也纳入要求，数量由计划声明并固定。
- [ ] 验证组合动作、静态重组及逐关节旋转；失败部件输出原因和区域，不用总分掩盖。
- [ ] 跑一次安装环境下的完整流程，再断网跑一次；缓存复用与新计算分别注明。
- [ ] 提交报告、策略、模型清单及适量代表产物，记录成功率/拒收率、运行时间和显存，
  不把论文指标或单个成功小样当成赵云全流程成功。

验收：全部本轮必需部件和动作检查通过，`humanInteractions=0`，无秘密联网依赖；
结果清楚区分 `source/reference/geometric/generated`。若部分隐蔽区域无法可靠补全，
自动流程可验收为“能够正确拒收”，但全角色质量验收仍是失败，不标记本任务 DONE。

## 6. 拟定接口与输出契约（尚未实现）

目标用户入口不要求手填补图计划。以下为设计示例，当前仓库尚不可运行：

```bash
python -m spinetools.completion.run \
  --sam-run /opt/spinetools/output/zhaoyun-split \
  --output /opt/spinetools/output/zhaoyun-completed \
  --model-dir /opt/spinetools/completion-models \
  --device cuda --offline
```

可选：`--video`、`--reference-dir`、`--policy`、`--resume`、`--dry-run`。
输入明确为 SAM run 的根目录，包含 `source/`、`prompts/`、`masks/`、`parts/`、`rig/`。
参考目录与视频只能使用显式传入的路径。

新增部件字段契约：

- `sourceBBox`：保留输入可见片的原始裁剪框。
- `completedBBox`：补全片的新裁剪框，允许超出原图范围；记录画布偏移，不截掉新增区域。
- `pivotSource`：源坐标锚点；`pivotLocal = pivotSource - completedBBox[:2]`。
- `visibleMask/fullMask/repairMask/protectedMask`：同一声明画布、同一源坐标变换。
- `repairMask`：允许新增内容的域，不能与保护区相交；对 Alpha 过渡的例外必须事先声明。
- `provenance`：每像素/区域的 `source/reference/geometric/generated/transparent` 来源。
- `missingTextureRegions`：检测到的缺失、所选补全及仍未解决区域，不能固定为空。
- `autoStatus/reasonCodes/uncertainty`：自动结论，不覆盖原始上游审核记录。
- `testMotionRange`：验收动作范围和时间采样；原地姿势通过不代表任意动作通过。

拟定目录：

```text
completed-run/
  run.json                       # 输入/配置/模型哈希、状态、预算、版本
  plan.json                      # 自动推导的需求、轮廓假设、遮挡关系、必需部件
  masks/                         # visible/full/repair/protected，附坐标声明
  candidates/<part>/<attempt>/    # 未通过和通过的候选及指标
  parts/                         # 自动选中的完整 RGBA；整包失败时仅为诊断
  provenance/                    # 像素来源和引用的帧/区域
  rig/component-manifest.json    # 显式新版契约
  reports/                       # 输入、静态、旋转、性能、模型环境报告
  preview/                       # 自动生成的对比图/旋转动图，不是人工必审环节
```

状态机：`PREFLIGHT → PLAN → GENERATE → VERIFY → RETRY | SUCCEEDED | FAILED`。
每个运行都产生终态报告；不设计 `REVIEW`、`WAITING_FOR_USER`。遇不可满足的环境/许可条件
可以报告失败并结束，不能绕过检查自动部署其他未批准的外部服务。

## 7. 默认实验参数和质量门

以下是开发起点，不是已验证最优值。发布策略必须写明版本，所有阈值由 AC-04 开发集校准
后冻结；运行时不能自动降低阈值以提升通过率。

| 项目 | 起点/要求 |
|---|---|
| 生成候选 Seed | 从基础 Seed 42、部件 ID、轮次确定性派生，记录实际值 |
| 每轮候选数 / 最大轮数 | 4 / 3；最多 12 个生成候选/部件 |
| SDXL 局部推理画布 | 约 1024，保留宽高比和上下文；输出回到源图尺度 |
| SDXL steps / guidance | 30 / 5；只对需要生成的部件使用 |
| SDXL strength | 有纹理底稿 0.6；基本空缺 0.9，按路线固定 |
| 接缝羽化 | 源图尺度 0–1 像素，仅新增区内，不改保护区 |
| 单候选超时 / 全任务时限 | 初始 300 秒 / 7200 秒，可显式配置，报告实际限制 |
| 受保护 RGBA 改变数 | 0，硬门；正常参考移植也不能改此区 |
| mask/坐标/输出一致性 | 全部通过，硬门 |
| 原图可见覆盖 | 先修复程序误删；未分配部分必须归因或拒收，不能隐瞒 |
| 合成遮挡隐藏区轮廓 IoU | 初始目标 ≥0.95；按类别单独报告 |
| 合成遮挡 RGB MAE | 初始目标 ≤8/255，在已知前景隐藏区及边缘合成视图分别计算 |
| 合成遮挡轮廓边缘距离 | 初始目标 95 分位 ≤1 个源像素 |
| 静态重组 | 保护区不变，轮廓无未声明扩张；全图误差不得掩盖局部失败 |
| 关节测试 | 扫描默认 ±15° 及组合姿态；有动作时覆盖完整要求范围 |
| 脱离模型的恶意负例 | 所有硬性违规负例必须拒绝，不能由高相似分抵消 |
| 真正不可见区域 | 无真值，不套用“还原准确率”；用一致性/结构/动作门和不确定性拒收 |

需要检查模型是否把“一个肩甲”补成“整个人物”、生成区域面积、骨轴方向、颜色与纹理差异。
这些自动指标不能证明艺术设定正确；当不同轮廓候选无法形成可信结论时返回失败。
上下文或预算不足时，不启动无限调参搜索。

## 8. 测试分层与提交要求

1. CPU 单元测试：去噪、最终 coverage、Alpha 污染、坐标、几何、状态机、缓存和超时。
2. 固定合成遮挡测试：输入/真值隔离，重复运行，按类别统计，不依赖人工 golden 候选。
3. GPU 后端探针：单后端环境、有限样例、离线检查和模型版本审计。
4. 赵云小样集成：四类小样全部通过后才进入全角色。
5. 全角色/故障集成：正确输出、错误拒收、断点恢复、动态测试和新 Docker 复跑。

代码提交建议以任务 ID 命名，例如 `fix(completion/AC-01): ...`；每项完成时更新本文件状态、
测试命令、对应 commit 和证据位置。先提交代码/测试，再提交少量可追溯产物，不把大型模型
混入仓库。文档中新增 CLI 必须标注实现状态；模型探针通过与质量验收通过分别记录。

本次计划不修改现有分割实现，不更新 expected hashes，不运行生成模型。原图、已有视频、
SAM 基线及历史归档继续保留。
